Phase 2: Error Handling & Recovery Branches
Branch 1: Empty Input Form
User submits empty text area or blank subject/body.
→ Renders "Empty Message Details" Error
Recovery: "Try Again" or Jump Chips (SMS, Email, URL, Phone)
Branch 2: Unreadable / Blurry Screenshot
Uploaded image has no readable OCR text or valid QR matrix.
→ Renders "Could Not Read Screenshot" Error
Recovery: Polite lighting advice & option to paste link manually
Branch 3: File Too Large (> 16 MB)
Screenshot exceeds max file upload limit (HTTP 413).
→ Renders "File Too Large" Error
Recovery: Guidance to compress or crop screenshot
Branch 4: Broken Link / 404 Route
User navigates to invalid URL path.
→ Custom Branded 404 Page
Recovery: "Back to Home" + 4 Quick Navigation chips

User Flow Architectural Notes

  • 1

    Zero Dead-End Architecture

    Every error, empty state, and completion screen includes at least two explicit escape hatches ("Try Again", "Back to Home", or "Check Another Content"), ensuring users never encounter an inescapable dead end.

  • 2

    Multi-Modal Input Symmetry

    Text pasting and image uploading (OCR & QR) follow identical processing workflows, resulting in the same standardized explainable risk output card format regardless of input modality.
